# DFU32

DFU32 is ESP32 firmware that flashes nRF52 boards over BLE using Nordic **legacy** DFU. You upload a firmware zip either over the web UI or Chrome serial connection from https://dfu32.app. You then configure a target (DFU32 remembers several, one of them the default) and can flash once that target is in BLE DFU mode.

The motivating use case was to flash MeshCore LoRa repeaters that are not usually within BLE range of a phone but in a location with WiFi that could be close to a small dedicated ESP32.

## Flash ESP32

The installer page at **[dfu32.app](https://dfu32.app/)** flashes DFU32 over USB from a desktop browser with Web Serial. Pick your board, click **Connect device**, then **Install DFU32**.

You could also flash using `esptool.py`:

```bash
esptool.py --chip auto -p PORT write_flash 0x0 dfu32-feather_esp32s3-merged.bin
```

The merged image is for a fresh install and resets settings (WiFi, token, targets). To update a running DFU32 from its web UI (**System → Firmware update**), use the app-only `dfu32-<board>.bin` from the same release instead (releases up to v0.4.0-rc.10 don't carry it: take `dfu32.bin` from the `dfu32-<board>` artifact of the release's Actions run). Each release also has `dfu32-release.json` (earlier ones get it from a one-off backfill), which lists every image with its SHA-256 and, per board, where each flash part sits inside the merged image (SPEC §9.4).

### Preview the installer page

dfu32.app only changes when a stable release is published (SPEC §9.4). To look at the page itself, copy in ESP Web Tools and esptool-js (from hash-pinned npm tarballs; `web/vendor/` is git-ignored) and serve `web/`. There is no firmware to install this way:

```bash
python3 tools/fetch_esp_web_tools.py --site web && python3 -m http.server -d web 8000
```

To install your own build from the page, assemble a site under `build/site` (git-ignored) the way the CI `pages` job does. Run `dfu32_web_manifest.py` once per board you built, then list the build in `versions.json`; with no releases it is the only version, labelled "latest, from main":

```bash
mkdir -p build/site && cp -R web/. build/site/
python3 tools/dfu32_web_manifest.py build/feather_esp32s3 --board feather_esp32s3 --site build/site --baseline partitions/baseline.json
echo '[]' > build/releases.json
python3 tools/dfu32_web_versions.py --site build/site --releases build/releases.json --assets build/releases
python3 tools/fetch_esp_web_tools.py --site build/site && python3 -m http.server -d build/site 8000
```

## Building

You need ESP-IDF **v6.1** (for example installed with `eim`). Activate it in your shell, then pick a board profile with `--preset`. Each profile sets the chip target, flash size, partition table, PSRAM, console and pins. Each preset (see [CMakePresets.json](CMakePresets.json)) builds in its own directory at `build/<profile>`.

Build:

```bash
idf.py --preset feather_esp32s3 build
```

Flash and monitor:

```bash
idf.py --preset feather_esp32s3 -p /dev/cu.usbmodem1101 flash monitor
```

Use your own serial port in place of `/dev/cu.usbmodem1101`.

You can set `IDF_PRESET` once and drop `--preset`:

```bash
export IDF_PRESET=feather_esp32s3
idf.py build flash monitor
```

To build every profile in turn:

```bash
python3 tools/build_all.py
```

| Profile | Board | Flash / PSRAM |
|---|---|---|
| `feather_esp32s3` (first preset) | Adafruit Feather ESP32-S3 #5477 | 4 MB / 2 MB |
| `feather_esp32_v2` | Adafruit Feather ESP32 V2 | 8 MB / 2 MB |
| `esp32s3_n16r8` | Generic ESP32-S3 N16R8 DevKitC | 16 MB / 8 MB |
| `rak11200_rak19007` | RAKwireless WisBlock RAK11200 on a RAK19007 base | 4 MB / 8 MB (4 MB mapped) |
| `xiao_esp32s3` | Seeed Studio XIAO ESP32S3 (or XIAO ESP32S3 Sense) | 8 MB / 8 MB |
| `xiao_esp32c5` | Seeed Studio XIAO ESP32C5 | 8 MB / 8 MB |

PSRAM is required. A board without it won't boot this firmware.
